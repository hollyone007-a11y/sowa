# SOWA

Рабочая система учёта жилья для агентства: адреса и свободные места, жильцы,
оплаты наличными и удержания из зарплаты, залоги, текущие и старые долги,
расходы по объектам, заявки на заселение по QR-коду.

**Адрес:** https://hollyone007-a11y.github.io/sowa/

Это боевая версия. Демо-режима нет: все данные живут в Supabase, вход только по
учётной записи. Без ключей Supabase сборка честно показывает экран «база не
подключена» вместо формы входа, которая всё равно не сработает.

## Что умеет

- адреса: вместимость, свободные места, аренда объекта, собрано, долг;
- жильцы, сгруппированные по адресам, с поиском и фильтрами;
- оплата в одно нажатие или частичная суммой;
- переселение, изменение цены, залог и выселение — в одной карточке жильца;
- перенос прошлого месяца одной кнопкой прямо на пустом месяце;
- QR-код на каждый адрес: человек сканирует его у входа, заполняет анкету, и
  она попадает во вкладку «Заявки» — менеджер заселяет одним нажатием;
- обновление QR-кода мгновенно выводит старую ссылку из строя;
- расходы по объектам (коммуналка, ремонт, услуги) с учётом в марже;
- финансы: начислено, собрано, долг месяца, долг за прошлые месяцы, аренда,
  расходы, разница, разбивка по адресам и список должников;
- экспорт CSV (разделитель `;` и BOM — открывается в чешском Excel как есть);
- защищённая анкета жильца с печатью или сохранением в PDF;
- роли `admin`, `manager`, `accountant`, `viewer` — и в интерфейсе, и в RLS;
- светлая и тёмная тема, вёрстка от 390 px, PWA.

## Настройка Supabase

Без этого шага приложение не заработает.

1. Создайте проект на [supabase.com](https://supabase.com).
2. В проекте: **Settings → API**. Оттуда понадобятся два значения —
   **Project URL** и ключ **anon public**. Ключ `anon` предназначен для
   браузера, он не секретный; `service_role` не используется нигде и его
   публиковать нельзя.
3. Примените схему. Либо через CLI:

   ```bash
   npx supabase link --project-ref YOUR_PROJECT_REF
   npx supabase db push
   ```

   либо вручную: откройте **SQL Editor** и выполните целиком файл
   `supabase/migrations/20260727000001_initial_schema.sql`.

4. В **Authentication → Users** нажмите **Add user** и создайте свою учётную
   запись с паролем.
5. В **Authentication → URL Configuration** добавьте
   `https://hollyone007-a11y.github.io/sowa/` в **Site URL** и в
   **Redirect URLs**.

**Первая созданная учётная запись автоматически становится администратором.**
Все следующие получают роль `viewer` — поднять роль можно в таблице
`public.profiles`. Пароль забытой учётной записи меняется там же, в Supabase →
Authentication → Users.

## Публикация

1. В репозитории: **Settings → Secrets and variables → Actions → New repository
   secret**. Добавьте два секрета:

   - `VITE_SUPABASE_URL` — Project URL из шага 2;
   - `VITE_SUPABASE_ANON_KEY` — ключ `anon public`.

2. **Settings → Pages → Source: GitHub Actions.**
3. Запустите **Actions → Deploy to GitHub Pages → Run workflow** (или сделайте
   любой push в `main`).

Дальше каждый push в `main` пересобирает и публикует сайт. База пути берётся из
имени репозитория, поэтому переименование ничего не ломает.

## Локальный запуск

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env   # и впишите свои значения
npm run dev
```

## Права

| Действие | admin | manager | accountant | viewer |
|---|:-:|:-:|:-:|:-:|
| Просмотр адресов и жильцов | ✓ | ✓ | ✓ | ✓ |
| Адреса, QR-коды и расходы | ✓ | ✓ | — | — |
| Жильцы, переселение, выселение | ✓ | ✓ | — | — |
| Заявки по QR: заселить или отклонить | ✓ | ✓ | — | — |
| Оплаты и перенос месяца | ✓ | ✓ | — | — |
| Финансы и экспорт | ✓ | ✓ | ✓ | — |
| Паспортные анкеты | ✓ | ✓ | — | — |
| Удаление записей | ✓ | — | — | — |

Права проверяются дважды: в интерфейсе и в PostgreSQL RLS. Скрытая кнопка не
считается защитой.

Анкету по QR-ссылке заполняет кто угодно без входа — это единственное, что
доступно без сессии.

## Устройство

Приложение не обращается к Supabase напрямую: всё идёт через один интерфейс
`Backend` (`src/lib/backend.ts`). Благодаря этому тесты гоняют настоящие
сценарии — вход, загрузку месяца, оплату, приём и одобрение заявки по QR —
против интерфейса, без базы и без единой строки тестового кода в боевой сборке.

Логотип — сова под крышей — описан геометрией и растеризуется в иконки:

```bash
npm run icons
```

## Персональные данные

Анкета создаётся в одной транзакции с жильцом, документные поля лежат в
отдельной таблице `resident_profiles_private`, закрытой RLS для бухгалтера и
наблюдателя. До реальной эксплуатации определите срок хранения, законное
основание обработки и список сотрудников с доступом — подробнее в
[SECURITY.md](SECURITY.md).
